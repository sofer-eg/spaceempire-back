# Point defence — сбивание торпед (TASK-112)

Источник: ЧТЗ doc-1 §3 FR-008, §5.3, риск R-04. Механизм сбиваемости сделан в
TASK-100.3.5.6; эта задача закрывает разрыв «механизм есть, но недостижим».

## Что было

`domain.Torpedo` реализует `Damageable`, есть `EntityKindTorpedo`,
`sector/projectile_combat.go` с `isProjectileTargetKind` / `fireLaserAtProjectile`,
исход `Killed` без сплэша и реап в `tickTorpedos`. Но:

- `AttackCommand` отвергала любой `Target.Kind != EntityKindShip`, то есть навести
  лазер на торпеду было нельзя ни игроку, ни AI-кораблю;
- `acquireDroneTarget` и `combat.SelectTowerTarget` сканировали только `s.ships`.

Итог: торпеду нельзя было сбить вообще.

## Три пути огня по торпеде

| Путь | Кто решает | Гейт враждебности |
|------|-----------|-------------------|
| `AttackCommand` → `fireLaserAtProjectile` | игрок / AI явно | **нет** |
| дрон (`acquireDroneTorpedo`) | автоматика | **есть** |
| лазерная башня (`acquireTowerTorpedo`) | автоматика | **есть** |

### Правило враждебности (решение по этой задаче)

- **Автоматический** огонь гейтится. Point-defence, сбивающий торпеды своей
  стороны, хуже отсутствующего, а дрон не может спросить владельца, что тот имел
  в виду.
- **Приказанный** огонь неизбирателен — консистентно с friendly-fire сплэшем
  (R-02) и это единственный способ **отменить свою торпеду**, что легитимный ход.

Гейт живёт в `nearestHostileTorpedo` (кандидат-сет автоматики), а не в
`fireLaserAtProjectile`, поэтому приказ проходит без исключений в боевом коде.

## Реализация

- `attackTargetable(shipID, ref)` — набор целей `AttackCommand`: другой корабль
  **или** `isProjectileTargetKind`. Статика остаётся player-unattackable by design
  (TASK-53.2) — прецедент, которому эта задача следует наоборот.
- `nearestHostileTorpedo(s, from, radius, hostile)` — ближайшая живая торпеда в
  радиусе, у которой предикат подтвердил враждебность.
- `acquireDroneTorpedo` — радиус тот же, что у ship-захвата
  (`droneSpec.FireRange × droneAcquireFactor`); оракул — `w.relations` (игрок сам
  себе не враждебен, поэтому свои торпеды исключены без спец-случая).
- `acquireTowerTorpedo` — радиус `towerSpec.Range`; оба предиката (`w.hostile` для
  игровых башен, `w.raceHostile` для расовых) принимают **корабль**, поэтому
  враждебность торпеды судится по её пусковому кораблю (`Torpedo.OwnerShipID`).
  Пусковой корабль вне сектора → башня не стреляет: судить нечего, а «любой
  корабль этого игрока» — это огонь по чужому корпусу.
- **Приоритет цели:** и дрон, и башня сначала ищут корабль; перехват занимает
  простаивающие тики. Дрон, занятый враждебным кораблём, торпеду не трогает.
- **Реап не меняется:** ни `fireLaserAtProjectile`, ни `fireTowerAtTorpedo`, ни
  дрон не удаляют торпеду. Все концы жизни торпеды — в `tickTorpedos`, который
  идёт после них и отдаёт `impact(killed)` без сплэша (§5.3).
- Урон по торпеде — только HP (щита нет); kill-атрибуции нет — за сбитую торпеду
  награда не платится.

## Фронт

- Торпеда на канвасе стала pickable (`ObjectLayer`, hit-circle) — в отличие от
  ракет и дронов, которые остаются `pointerEvents: none`, потому что у них нет HP.
- Меню объекта для `kind: 'torpedo'`: «✶ Сбить торпеду» → `sendAttack` с
  `EntityKind.Torpedo`. Заголовок — класс боеприпаса («Торпеда «Огненная Буря»
  #14»), не сырой id; для своей торпеды подсказка «Сбить свою торпеду (отмена
  пуска)».
- Меню закрывается, как только торпеда исчезла из `world.torpedos`
  (`visibleMenu`), — она живёт секунды.
- Контакт-строки у торпед нет (живут секунды, список бы дрожал) — только канвас.
- **Известное ограничение z-порядка:** корпуса кораблей рисуются поверх снарядов,
  поэтому торпеду в гуще кораблей мышью не подцепить, пока она не отойдёт. Это
  свойство существующей отрисовки, не этой задачи.
